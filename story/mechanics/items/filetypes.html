filetypes File Type Hierarchy (from common → ultra‑rare) Your order already makes sense. Here it is formalized as a rarity ladder: HTML / Tiny Text Files Documents (txt, doc, pdf) Photos (jpg, png) Music (mp3, wav) Videos (mp4, mkv) Programs (exe, bin, scripts) Games (large, multi‑file, high value) System Files (OS components, drivers, configs) Schemas (data structures, blueprints, API specs) Tables (csv, structured data) Full Databases (sql, nosql, proprietary formats) Encrypted Files Personal Organization Government Spy / Intelligence Occult / Forbidden Unknown (highest rarity) This gives you a 12‑tier rarity system with sub‑rarities inside the encrypted tier. Core Stats Every File Has Each file instance should carry these stats: size (KB → TB) moneyValue (sell price) researchValue (XP, tech unlocks, lore) compressionLevel (0 → N times compressed) quality (0–100 or letter grade) isCorrupted (boolean, chance increases with rarity/age) isInfected (boolean, contains virus payload) Optional advanced stats: origin (city, server, faction, brand) permissions (read/write/execute) fileAge (affects corruption chance) fileSignature (used for detection, quests, or hacking) How to Scale These Stats (Mathematical Model) 1. Size Scaling Each file type has a size range: HTML: 10 1 – 10 3 bytes Documents: 10 3 – 10 5 bytes Photos: 10 5 – 10 7 bytes Music: 10 6 – 10 8 bytes Videos: 10 7 – 10 10 bytes Programs/Games: 10 6 – 10 10 bytes Databases: 10 8 – 10 12 bytes Encrypted: variable, but usually 2×–10× larger than unencrypted equivalents Formula for random size inside a tier: size = minSize × 𝑟 𝑘 Where: 𝑟 = random number 1–3 𝑘 = tier index (0–12) This gives exponential size growth across tiers. 2. Money Value Scaling Money value should scale with: file type rarity size quality corruption infection compression Base formula: value = ( size 𝛼 ) ⋅ 𝑅 ⋅ 𝑄 ⋅ 𝐶 Where: 𝛼 = 0.6–0.9 (sub‑linear so huge files don’t break economy) 𝑅 = rarity multiplier (1 → 1000+) 𝑄 = 1 + quality 100 𝐶 = 1 − 0.2 ⋅ compressionLevel Corruption penalty: value = value ⋅ ( 0.5  if corrupted ) Infection penalty or bonus (depending on gameplay): value = value ⋅ ( 1.5  if infected and you sell to black market ) 3. Research Value Scaling Research value should scale faster than money value to encourage scanning instead of selling. researchValue = size 𝛽 ⋅ 𝑅 Where: 𝛽 = 0.8 – 1.2 depending on how fast you want tech progression 𝑅 = rarity multiplier Encrypted files get a huge bonus: researchValue = researchValue ⋅ ( 2 – 20 ) 4. Corruption Chance Lower tiers rarely corrupt, higher tiers often corrupt. 𝑃 ( corrupt ) = 0.01 ⋅ 𝑇 1.3 Where: 𝑇 = tier index (1–12) Examples: Tier 1 (HTML): 1% Tier 6 (Programs): ~15% Tier 12 (Unknown encrypted): ~40% 5. Infection Chance Viruses appear more often in: programs games system files encrypted intelligence files Formula: 𝑃 ( infected ) = 𝐵 + 0.02 ⋅ 𝑇 Where: 𝐵 = base infection chance by file type (e.g., programs = 10%, photos = 1%) 𝑇 = tier index Compression System Each compression pass reduces size but also reduces value. size 𝑛 = size 0 ⋅ ( 0.7 ) 𝑛 value 𝑛 = value 0 ⋅ ( 0.85 ) 𝑛 This creates a strategic choice: compress to save storage but lose money value Virus System Integration If a file is infected: it can spread to other files it can damage your system it can be extracted and sold it can be researched for virus XP Virus severity tiers: Low: slows system Medium: corrupts files High: steals money Critical: rootkits, worms, trojans Legendary: movie‑style viruses (your earlier
